# 問13｜排他制御（Mutex）

## 目標
複数のゴルーチンから同じデータを同時に読み書きするときに発生する「データ競合（Data Race）」を、`sync.Mutex` による排他制御で防ぐ方法を学びます。

## 今回の演習で学ぶこと
この問題では、並行処理における「安全な共有データの操作」の基礎を学びます。

---

### データ競合（Data Race）とは何か？

銀行口座の残高を2つのゴルーチンが同時に更新する例で考えてみましょう：

```
残高: 1000円

ゴルーチンA: 500円入金
  1. 残高を読む → 1000
  2. 1000 + 500 を計算 → 1500
         ← ここでゴルーチンBが割り込む！
ゴルーチンB: 200円入金  
  1. 残高を読む → 1000（まだ更新されていない！）
  2. 1000 + 200 を計算 → 1200
  3. 残高を書く → 1200

ゴルーチンA: 
  3. 残高を書く → 1500

最終残高: 1500円（本当は1700円のはず！）
```

200円が消えてしまいました。これが**データ競合**です。

---

**1. データ競合とは何か**

複数のゴルーチンが同じ変数やマップに「同時」に書き込もうとすると、データが壊れたりパニックが起きたりします。

```go
m := make(map[string]int)

go func() { m["key"] = 1 }() // ゴルーチンA
go func() { m["key"] = 2 }() // ゴルーチンB（同時アクセスでパニック！）
```

Goはマップへの並行アクセスに対してパニックで応答します（意図的な設計です）。

---

**2. sync.Mutex でロック**

`Mutex`（Mutual Exclusion = 相互排除）は「今から私がここを使うから他は待ってね」という鍵を提供します。

```go
type SafeMap struct {
    mu   sync.Mutex       // ロック（鍵）
    data map[string]int   // 保護されるデータ
}

func (s *SafeMap) Set(k string, v int) {
    s.mu.Lock()         // 鍵をかける（他のゴルーチンはここでブロック）
    defer s.mu.Unlock() // 処理が終わると自動で鍵を開ける
    s.data[k] = v       // 安全に書き込む
}
```

Mutex の動作イメージ：

```
ゴルーチンA: Lock()を呼ぶ → 鍵取得 → 処理中 → Unlock()
ゴルーチンB: Lock()を呼ぶ → 鍵がない！待機 ←→ Aが Unlock → 鍵取得 → 処理
```

---

**3. Lock と Unlock のルール**

- `Lock()` したら**必ず** `Unlock()` を呼ぶ（呼ばないとデッドロック）
- `defer` を使うと安全（パニック時でも必ず解放される）
- `Lock()` 中は他のゴルーチンの `Lock()` がブロックされる
- `Mutex` は値コピーしてはいけない（必ずポインタで渡す）

```go
// 正しい使い方
func (s *SafeMap) Set(k string, v int) {
    s.mu.Lock()         // ロック
    defer s.mu.Unlock() // 必ず解放
    s.data[k] = v
}

// デッドロックの例（同じゴルーチンが Lock を2回呼ぶ）
s.mu.Lock()
s.mu.Lock()  // ← 自分自身をブロックしてしまう！永遠に解放されない
```

---

**4. Mutex の種類と使い分け**

| 型 | 読み込み | 書き込み | 使いどころ |
|---|---------|---------|------------|
| `sync.Mutex` | 排他（1つずつ） | 排他（1つずつ） | シンプルな排他制御 |
| `sync.RWMutex` | **並行OK** | 排他（1つずつ） | 読み込みが多く書き込みが少ない場合 |

`sync.RWMutex` による最適化：「読み込みは複数同時でいい、書き込みだけ排他にしたい」場合は `sync.RWMutex` を使います。

```go
var rwmu sync.RWMutex

// 読み込み（複数ゴルーチンが同時に行える）
rwmu.RLock()
defer rwmu.RUnlock()
val := data["key"]

// 書き込み（排他）
rwmu.Lock()
defer rwmu.Unlock()
data["key"] = newVal
```

---

**5. -race フラグでデータ競合を検出**

Goのビルドツールに `-race` フラグを付けると、実行時にデータ競合を検出してくれます：

```bash
go test -race ./...
go run -race main.go
```

開発中は定期的に `-race` で確認するのが良い習慣です。
