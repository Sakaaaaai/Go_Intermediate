# 問11｜バッファ付きチャネル

## 目標
送受信のタイミングが合わなくてもブロックしない「バッファ付きチャネル」を学び、通常チャネルとの違いを理解します。

## 今回の演習で学ぶこと
この問題では、チャネルに「容量（バッファ）」を持たせることで並行処理の柔軟性が増すことを学びます。

---

### バッファ付きチャネルが必要な場面

Q10で学んだバッファなしチャネルは「送受信が即座に同期する」という特徴がありました。しかし、送信側と受信側のスピードが異なる場合は問題が起きます：

```
送信側（プロデューサー）: 100件/秒でデータを生成
受信側（コンシューマー）: 50件/秒で処理

バッファなし: 送信側は受信側が1件処理するたびに待機 → 50件/秒しか出せない
バッファあり: 差分をバッファに蓄えて、送信側が先に進める → 100件/秒で送れる
```

実際の郵便ポスト（バッファ）と郵便配達員（受信側）の関係に似ています。ポストがあれば、配達員が来ていなくても手紙を投函できます。

---

**1. バッファなし vs バッファあり**

```go
ch1 := make(chan string)    // バッファなし：送信側は受信側が受け取るまで待機
ch2 := make(chan string, 3) // バッファあり：3つまでは受信されなくても送れる
```

---

**2. バッファ付きチャネルの動作**

バッファが満杯でない間は、受信側を待たずに送信し続けられます。

```go
ch := make(chan string, 2) // 容量2のバッファ付きチャネル

ch <- "Apple"   // バッファに入る（ブロックしない）
ch <- "Banana"  // バッファに入る（ブロックしない）
// ch <- "Cherry" // ← バッファ満杯なのでここでブロック！（受信されるまで待機）

// 後から受信できる
fmt.Println(<-ch) // "Apple"  （先入れ先出し = FIFO）
fmt.Println(<-ch) // "Banana"
```

> **FIFO（First In First Out）**: チャネルは「入れた順に取り出せる」キュー（待ち行列）です。

---

**3. バッファのサイズ感の図解**

```
バッファなし（容量0）:
[送信] → [受信] （同時でなければブロック）

バッファ2:
[送信] → [Apple][Banana] → [受信]
            ↑ここが埋まるとブロック

バッファ満杯でさらに送信しようとすると:
[送信→ブロック！] [Apple][Banana] → [受信]（受信が起きると送信が解除）
```

---

**4. for range でまとめて受信**

チャネルを `close` すると `for range` で全データ受信後にループを抜けます。

```go
ch := make(chan int, 3)
ch <- 1; ch <- 2; ch <- 3
close(ch) // これ以上送信しないことを宣言

for v := range ch {
    fmt.Println(v) // 1, 2, 3 と順に受信される
}
// close されているので range が自然に終わる
```

> **重要**: `close` されていないチャネルで `for range` すると、全データ受信後にブロックし続けます（デッドロック）。必ず `close` すること。

---

**5. 使いどころ**

- **プロデューサー・コンシューマーパターン**: 生成と消費のスピードが異なる場合のバッファリング
- **結果の非同期収集**: 非同期に複数の結果を収集してから後でまとめて処理する場合
- **セマフォ（同時実行数の制限）**: バッファ付きチャネルのサイズで最大同時実行数を制限できる
