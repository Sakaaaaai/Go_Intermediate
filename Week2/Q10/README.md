# 問10｜チャネル（Channel）基礎

## 目標
ゴルーチン間で安全にデータをやり取りするためのパイプ「チャネル（Channel）」の基本的な送受信を学びます。

## 今回の演習で学ぶこと
この問題では、Goの「並行処理間の通信」の要となるチャネルの仕組みを学びます。

---

### チャネルが必要な理由　〜 共有変数の危険性

ゴルーチン間でデータをやり取りする最も単純な方法は「共有変数」ですが、これは危険です：

```go
// 危険な例：複数ゴルーチンが同じ変数を読み書き
var result string

go func() {
    result = "Hello from A"  // ゴルーチンAが書き込む
}()
go func() {
    result = "Hello from B"  // ゴルーチンBも書き込む（競合！）
}()
// result の最終値は不定（どちらが後に書いたかによる）
```

チャネルを使うと、データのやり取りが**順番に、かつ安全に**行われます。
Goの設計哲学「**メモリの共有で通信するのではなく、通信でメモリを共有せよ**」の体現です。

---

**1. チャネルとは**

チャネルは、2つのゴルーチン間をつなぐ「パイプ」です。一方が値を送信すると、もう一方がそれを受信します。共有変数を直接使うよりずっと安全にデータを受け渡しできます。

```
ゴルーチンA  ──── ch ──→  ゴルーチンB（またはメイン）
    送信 (ch <- value)         受信 (value := <-ch)
```

---

**2. チャネルの作成**

```go
ch := make(chan string)   // string 型のチャネルを作成
ch2 := make(chan int)     // int 型のチャネルを作成
ch3 := make(chan []byte)  // []byte 型のチャネルを作成

// 型は任意（構造体も可）
type Message struct{ From, Text string }
ch4 := make(chan Message)
```

---

**3. 送信と受信**

```go
// 送信（チャネルに値を入れる）
ch <- "Hello"

// 受信（チャネルから値を取り出す）
msg := <-ch
fmt.Println(msg) // "Hello"

// 受信して変数に使わない場合
<-ch  // 受信だけして捨てる（完了を待つだけ）
```

送信は `ch <-`（矢印がchに向かっている）、受信は `<-ch`（矢印がchから出ている）と覚えると分かりやすいです。

---

**4. ブロッキング（重要！）**

バッファなしチャネル（デフォルト）の動作は：

- **送信側**：誰かが受け取るまでブロック（待機）する
- **受信側**：誰かが送ってくるまでブロック（待機）する

「ブロック」とは「その行で処理が止まる」ことです。これが「安全なデータ受け渡し」を実現する仕組みです。

```
タイムライン:
main:     make(ch) → <-ch（ここで待機！）... → msg受信 → 実行続行
goroutine: (起動) ... → ch <- "Hello"（mainが受け取るまで待機）
```

---

**5. ゴルーチンでの使い方**

```go
ch := make(chan string)

go func() {
    // 重い処理が終わったら結果を送信
    time.Sleep(100 * time.Millisecond)
    ch <- "Hello from Goroutine!" // 受信されるまでここで待機
}()

msg := <-ch // 送信されるまでここで待機
fmt.Println(msg)
// → "Hello from Goroutine!" が確実に表示される
```

`WaitGroup` との違い：チャネルは「完了通知」と「データ転送」を**同時に**行えます。
