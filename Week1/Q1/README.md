# 問1｜インターフェースの基礎

## 目標
Go言語における「インターフェース」の基本概念を理解し、異なる構造体を同じ型として扱う方法を学びます。

## 今回の演習で学ぶこと
この問題では、Goのインターフェースを使って「**異なる型を共通のルールで扱う**」設計パターンの基礎を学びます。

---

### インターフェースとは何か？　〜 まず「なぜ必要か」から理解しよう

例えば、「犬（Dog）」と「猫（Cat）」という2つの異なる型がある場合を考えてみましょう。

```go
type Dog struct{}
type Cat struct{}
```

それぞれが「しゃべる（Speak）」能力を持っているとします。もしインターフェースがなければ、`Dog` 用の関数と `Cat` 用の関数をそれぞれ個別に書かなければなりません：

```go
func SayHelloDog(d Dog) string { return d.Speak() }
func SayHelloCat(c Cat) string { return c.Speak() }
```

`Dog` でも `Cat` でも「ただ `Speak()` を呼びたいだけ」なのに、関数が2つ必要になってしまいます。**インターフェースを使うと、この問題を解決できます。**

---

**1. インターフェースとは何か**

インターフェースは「このメソッドを持っていれば、この型として扱っていいよ」という**約束事（契約）**を定義するものです。
Go言語の特徴として、`implements` のようなキーワードを書かなくても、必要なメソッドを実装しているだけで自動的にインターフェースを満たします。これを**ダックタイピング**（「アヒルのように歩き、アヒルのように鳴くなら、それはアヒルだ」）と言います。

```go
// Speaker インターフェース：Speak() メソッドを持てば Speaker として扱える
type Speaker interface {
    Speak() string
}
```

このインターフェースが言いたいことは「`Speak() string` というメソッドを持っていれば、どんな型でも `Speaker` として使えます」ということです。

---

**2. 構造体にメソッドを実装する**

`Dog` や `Cat` といった具体的な構造体に `Speak()` を実装するだけで、自動的に `Speaker` を満たします。
**「Speakerを実装する」と宣言しなくてよい**のがGoの特徴です。

```go
type Dog struct{}

func (d Dog) Speak() string {
    return "ワンワン"
}

type Cat struct{}

func (c Cat) Speak() string {
    return "ニャー"
}
```

> **ポイント**: `func (d Dog) Speak() string` の `(d Dog)` の部分を「**レシーバ**」と呼びます。これによって「この `Speak` は `Dog` 型のメソッドだよ」と Goに伝えます。

---

**3. インターフェース型を引数にとる関数**

関数の引数をインターフェース型にすることで、`Dog` でも `Cat` でも**同じ1つの関数**で処理できます。

```go
func SayHello(s Speaker) string {
    return s.Speak() // Dog でも Cat でも呼べる！
}
```

使う側はこう書きます：

```go
fmt.Println(SayHello(Dog{})) // "ワンワン"
fmt.Println(SayHello(Cat{})) // "ニャー"
```

将来 `Bird` 型を追加しても、`Speak()` を実装するだけで `SayHello` が使えます。**既存のコードを修正する必要がありません。**

---

**4. インターフェースのメリットまとめ**

| メリット | 説明 |
|----------|------|
| **柔軟性** | 異なる型を同じ型として扱える |
| **拡張性** | 新しい型を追加しても既存コード不変 |
| **テスト容易性** | モック（偽物）の差し替えが簡単 |
| **疎結合** | 実装の詳細を知らなくてよい |

## ヒント
- インターフェース定義のキーワードは `interface { ... }`
- 構造体のメソッド：`func (レシーバ 型名) メソッド名() 戻り値の型 { ... }`
- インターフェースを「実装した」宣言は書かなくていい（自動判定）
- `Dog{}` は「フィールドなしの Dog 型の値」を作る書き方
