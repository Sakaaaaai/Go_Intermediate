# 問6｜エラーのラップとアンラップ

## 目標
エラーに追加情報を付けて包み込む「ラップ（Wrap）」と、元のエラーを取り出す「アンラップ（Unwrap）」を使ったエラーハンドリングをマスターします。

## 今回の演習で学ぶこと
この問題では、実務で頻繁に使われる「エラーチェーン」の扱い方を学びます。

---

### エラーのラップとは？　〜 問題の背景を理解しよう

例えば、次のようなエラー処理を考えてみます：

```go
func LoadConfig() error {
    _, err := os.Open("config.txt")
    if err != nil {
        return err  // そのまま返してしまう
    }
    return nil
}
```

この場合、`LoadConfig()` を呼んだ側は「ファイルが開けなかった」ことはわかりますが、**「どの処理でそのエラーが起きたのか」**がわかりません。

エラーが複数の関数を経由するアプリでは「このエラーはどこで起きたの？」が重要な情報です。

---

**1. なぜラップが必要か**

```go
err := os.Open("data.txt")   // だけでは「何をしようとしてファイルを開こうとしたのか」わからない
```

上位の関数でエラーを受け取ったとき、「どのステップで失敗したのか」という**コンテキスト（文脈）**を追加したいことがよくあります。しかし、新しいエラーを作ってしまうと、元のエラーの情報が失われて「これはファイルがなかったエラーか？」を判定できなくなります。

---

**2. %w でラップする**

`fmt.Errorf` に `%w` を使うと、元のエラーを**包み込んで**保持できます。`%v` との違いは「元のエラーへの参照を維持する」かどうかです。

```go
func ReadFile(path string) error {
    _, err := os.Open(path)
    if err != nil {
        // 元のエラー（err）を %w で包み込んで返す
        return fmt.Errorf("ReadFile: ファイルを開けませんでした: %w", err)
        //                 ↑ コンテキスト情報        ↑ 元のエラーを保持
    }
    return nil
}
```

エラーメッセージは「外側の説明」+「元のエラー」という形でチェーン（連鎖）になります：

```
ReadFile: ファイルを開けませんでした: open data.txt: no such file or directory
└─ ラップしたエラー ─────────────────┘  └─── 元のエラー ──────────────────────┘
```

---

**3. errors.Unwrap で元のエラーを取り出す**

ラップされたエラーから1つ内側のエラーを取り出せます。

```go
err := ReadFile("dummy.txt")

cause := errors.Unwrap(err) // 1段階中のエラーを取り出す
fmt.Println(cause)          // open dummy.txt: no such file or directory
```

> **注意**: `errors.Unwrap` は1段階だけ剥がします。複数回ラップされている場合は複数回呼ぶ必要があります。

---

**4. %v と %w の違い**

| | `%v` | `%w` |
|--|------|------|
| エラーメッセージ | 同じ（文字列として埋め込む） | 同じ |
| 元のエラーへの参照 | **なし**（失われる） | **あり**（保持される） |
| `errors.Unwrap` | `nil` を返す | 元のエラーを返す |
| `errors.Is` / `errors.As` | 使えない | **使える**（Q7で学習） |

---

**5. 次のステップ：errors.Is との組み合わせ**

`errors.Unwrap` で1つ取り出すより、`errors.Is(err, target)` を使うと、何重にラップされていても特定のエラーが含まれているかを確認できます（Q7で学びます）。

---

## 問題文
`main.go` の `___` の部分を埋めてプログラムを完成させてください。

1. 存在しないファイル `"dummy.txt"` を `os.Open` で開こうとする関数 `ReadFile()` を完成させてください。
2. `os.Open` がエラーを返した場合、`"failed to open file: <元のエラー>"` という形で `%w` を使ってラップして返してください。
3. `main` 関数で返ってきたエラーに対して `errors.Unwrap` を呼び出し、元のエラー（原因）を取り出して表示してください。

## ヒント
- ラップ：`return fmt.Errorf("コンテキスト: %w", err)` （`%v` ではなく `%w` を使う）
- アンラップ：`cause := errors.Unwrap(wrappedErr)` でラップの1層を剥がす
- `nil` を `errors.Unwrap` に渡すと `nil` が返る（安全）
